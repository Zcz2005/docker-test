01 · 案例概述

什么是绿链溯源？

一个基于联盟链技术构建的农产品供应链数字化溯源平台

项目背景

中国是全球最大的农产品生产与消费国。然而，食品安全事件频发、假冒伪劣产品泛滥、 供应链信息孤岛严重，导致消费者难以验证产品真伪，企业品牌信任度受损， 监管部门追溯成本高昂。

绿链溯源（GreenChain）是一个面向农产品行业的联盟链溯源平台， 由农业合作社、加工商、物流公司、零售商、质检机构和监管部门共同参与治理。 平台将种植、采收、加工、检测、物流、零售等全链路数据上链存证， 消费者扫码即可查看完整溯源信息。

🎯

核心目标

  • 实现农产品从产地到餐桌的全链路可追溯
  • 确保溯源数据不可篡改、可审计
  • 提升消费者信任与品牌溢价能力
  • 降低监管部门的追溯成本
  • 支持快速召回与责任认定
🔗

为什么选择区块链？

  • 不可篡改性 — 历史记录一旦写入链上，任何参与方均无法单方面修改
  • 多方共识 — 联盟链各节点共同验证交易，避免单方造假
  • 透明可审计 — 授权方可随时查验完整历史记录
  • 智能合约 — 自动执行业务规则，减少人为干预
  • 跨组织协作 — 打破信息孤岛，建立信任机制

02 · 痛点分析

传统溯源体系面临的核心挑战

中心化数据库方案难以解决多方协作中的信任问题

❌ 传统中心化溯源

  • 数据可被单方篡改

    企业自有数据库，内部人员可修改历史记录，消费者无法验证真实性

  • 信息孤岛严重

    种植、加工、物流、零售各环节系统互不联通，数据碎片化

  • 追溯成本高昂

    出现食品安全事件后，跨组织协调追溯平均需要 7-15 天

  • 防伪能力薄弱

    二维码可被复制，溯源页面可被伪造，消费者难以辨别

  • 责任认定困难

    缺乏可信的时间戳和多方见证，纠纷中难以确定责任环节

  • 监管审计不便

    监管部门需逐一调取各方数据，效率低且可能被选择性提供

✅ 区块链溯源方案

  • 链上数据不可篡改

    联盟链共识机制保证写入后无法修改，哈希链式结构可检测任何篡改

  • 多方共建共享

    各参与方作为链上节点，数据实时同步，打破信息孤岛

  • 秒级精准追溯

    输入批次号即可在 3 秒内定位全链路信息，召回效率提升 90%+

  • 密码学防伪验证

    二维码关联链上哈希，扫码可验证数据完整性与来源真实性

  • 全程时间戳存证

    每个环节上链时间由区块链网络共同见证，法律效力更强

  • 监管实时可见

    监管节点拥有只读权限，可随时审计任意批次的全链路数据

📰 真实事件：为什么需要区块链溯源？

2018

疫苗冷链数据被篡改，传统数据库无法证明数据真实性，引发公众信任危机。若有区块链存证，任何温度异常修改都会被立即发现。

2020

进口冷链食品疫情追溯

新冠疫情中，进口食品溯源涉及多国多方，传统系统协调困难。区块链可实现跨境数据互信，快速定位问题批次。

某电商平台"有机"蔬菜被曝实为普通蔬菜贴标。区块链可验证有机认证上链记录，消费者可查验认证机构签名。

03 · 解决方案

绿链溯源平台核心功能

六大功能模块覆盖溯源全生命周期

01

数字身份管理

为每个参与方（农户、工厂、物流商等）分配基于非对称加密的链上数字身份（DID），所有上链操作均需私钥签名，确保操作可追溯至具体主体。

技术：ECDSA 签名 · X.509 证书 · DID
02

批次生命周期管理

从产品创建到消费完结，每个批次拥有唯一链上 ID。支持批次拆分（一大批分成多小批）和合并（多批合成一批），父子关系在链上完整记录。

支持：批次拆分 · 批次合并 · 状态机流转
03

物联网数据上链

对接温湿度传感器、GPS 定位、视频监控等 IoT 设备，关键环境数据自动采集并上链。智能合约设定阈值，温度超标自动触发预警。

设备：传感器 · GPS · RFID · 电子秤
04

质检报告存证

第三方检测机构将报告哈希上链，原始报告存储在 IPFS 分布式存储中。消费者可验证报告未被篡改，认证机构数字签名确保权威性。

存储：IPFS · 链上哈希 · 数字签名
05

消费者溯源查询

扫描产品包装上的二维码，即可查看从种植到零售的完整时间线。支持验证链上数据哈希，确认信息真实性。提供多媒体展示（图片、视频、地图）。

渠道：微信小程序 · H5 · APP
06

监管审计与召回

监管部门拥有链上只读审计权限，可实时监控、生成合规报告。发现问题批次后，一键发起召回，系统自动通知所有下游节点。

功能：实时审计 · 一键召回 · 合规报告

05 · 业务流程

有机番茄全链路溯源流程

从种植到消费的 6 大环节，12 次链上操作

环节 1：种植登记 🌱

操作主体：寿光绿野合作社 · 张农户

上链数据：地块编号、作物品种、种植日期、有机认证编号、施肥用药记录

链上操作：调用 createBatch() 创建产品批次，生成唯一批次 ID

IoT 数据：土壤湿度传感器、气象站数据自动采集上链

Hash: 0x1a2b3c... Tx: createBatch

环节 2：采收记录 🧺

操作主体：寿光绿野合作社 · 采收队

上链数据：采收日期、采收数量 (500kg)、采收人员、田间检测结果

链上操作：调用 addTraceRecord() 添加采收环节记录

质检前置：采收时进行农残快检，合格后方可进入下一环节

环节 3：加工包装 🏭

操作主体：潍坊绿野加工厂

上链数据：加工工艺、包装规格、生产日期、保质期、操作员信息

链上操作：调用 transferOwnership() 转移批次所有权，addTraceRecord() 记录加工信息

批次拆分：500kg 大批拆分为 1000 盒 × 500g 小批，父子关系上链记录

环节 4：质量检测 🔬

操作主体：山东省农产品质量检测中心

上链数据：检测报告编号、检测项目、检测结果、认证签章

链上操作：调用 submitQualityReport() 提交质检报告哈希

智能合约验证：合约自动检查报告签名是否来自认证机构白名单

环节 5：冷链物流 🚚

操作主体：顺丰冷链物流

上链数据：运输车辆、司机信息、GPS 轨迹、温湿度实时数据、交接节点

链上操作：调用 addTraceRecord() 记录物流节点，IoT 数据通过 submitIoTData() 自动上链

异常预警：温度超过 8°C 时，智能合约自动触发 Alert 事件通知相关方

环节 6：零售上架 🏪

操作主体：北京华联超市朝阳店

上链数据：收货确认、上架时间、销售价格、溯源二维码生成

链上操作：调用 confirmDelivery() 确认收货，generateQRCode() 生成消费者查询码

消费者体验：扫码查看完整 6 环节溯源时间线，验证链上哈希确认数据真实性

package main

import (
    "encoding/json"
    "fmt"
    "time"
    "github.com/hyperledger/fabric-contract-api-go/contractapi"
)

// ProductBatch 产品批次结构
type ProductBatch struct {
    BatchID       string `json:"batchId"`
    ProductName   string `json:"productName"`
    Category      string `json:"category"`
    Quantity      int    `json:"quantity"`
    Unit          string `json:"unit"`
    Status        string `json:"status"`
    CreatedBy     string `json:"createdBy"`
    CreatedAt     int64  `json:"createdAt"`
    ParentBatchID string `json:"parentBatchId"`
    MetadataHash  string `json:"metadataHash"`
    CurrentOwner  string `json:"currentOwner"`
}

// BatchContract 批次管理合约
type BatchContract struct {
    contractapi.Contract
}

// CreateBatch 创建新产品批次
// 仅授权农户组织可调用
func (c *BatchContract) CreateBatch(
    ctx contractapi.TransactionContextInterface,
    batchID string,
    productName string,
    category string,
    quantity int,
    unit string,
    metadataHash string,
) error {
    // 验证调用者身份
    clientMSPID, err := ctx.GetClientIdentity().GetMSPID()
    if err != nil {
        return fmt.Errorf("获取调用者身份失败: %v", err)
    }
    if clientMSPID != "FarmerOrgMSP" {
        return fmt.Errorf("仅农户组织可创建批次")
    }

    // 检查批次是否已存在
    existing, err := ctx.GetStub().GetState(batchID)
    if err != nil {
        return fmt.Errorf("查询失败: %v", err)
    }
    if existing != nil {
        return fmt.Errorf("批次 %s 已存在", batchID)
    }

    creator, _ := ctx.GetClientIdentity().GetID()

    batch := ProductBatch{
        BatchID:      batchID,
        ProductName:  productName,
        Category:     category,
        Quantity:     quantity,
        Unit:         unit,
        Status:       "CREATED",
        CreatedBy:    creator,
        CreatedAt:    time.Now().Unix(),
        MetadataHash: metadataHash,
        CurrentOwner: creator,
    }

    batchJSON, _ := json.Marshal(batch)
    return ctx.GetStub().PutState(batchID, batchJSON)
}

// TransferOwnership 转移批次所有权
func (c *BatchContract) TransferOwnership(
    ctx contractapi.TransactionContextInterface,
    batchID string,
    newOwner string,
) error {
    batch, err := c.GetBatch(ctx, batchID)
    if err != nil {
        return err
    }

    caller, _ := ctx.GetClientIdentity().GetID()
    if batch.CurrentOwner != caller {
        return fmt.Errorf("仅当前所有者可转移批次")
    }

    batch.CurrentOwner = newOwner
    batch.Status = "TRANSFERRED"

    batchJSON, _ := json.Marshal(batch)
    return ctx.GetStub().PutState(batchID, batchJSON)
}

// SplitBatch 批次拆分
func (c *BatchContract) SplitBatch(
    ctx contractapi.TransactionContextInterface,
    parentBatchID string,
    childBatchIDs []string,
    quantities []int,
) error {
    parent, err := c.GetBatch(ctx, parentBatchID)
    if err != nil {
        return err
    }

    totalQty := 0
    for _, q := range quantities {
        totalQty += q
    }
    if totalQty != parent.Quantity {
        return fmt.Errorf("拆分数量之和必须等于原批次数量")
    }

    for i, childID := range childBatchIDs {
        child := ProductBatch{
            BatchID:       childID,
            ProductName:   parent.ProductName,
            Category:      parent.Category,
            Quantity:      quantities[i],
            Unit:          parent.Unit,
            Status:        "CREATED",
            CreatedBy:     parent.CreatedBy,
            CreatedAt:     time.Now().Unix(),
            ParentBatchID: parentBatchID,
            CurrentOwner:  parent.CurrentOwner,
        }
        childJSON, _ := json.Marshal(child)
        ctx.GetStub().PutState(childID, childJSON)
    }

    parent.Status = "SPLIT"
    parentJSON, _ := json.Marshal(parent)
    return ctx.GetStub().PutState(parentBatchID, parentJSON)
}

// GetBatch 查询批次信息
func (c *BatchContract) GetBatch(
    ctx contractapi.TransactionContextInterface,
    batchID string,
) (*ProductBatch, error) {
    batchJSON, err := ctx.GetStub().GetState(batchID)
    if err != nil {
        return nil, fmt.Errorf("查询失败: %v", err)
    }
    if batchJSON == nil {
        return nil, fmt.Errorf("批次 %s 不存在", batchID)
    }

    var batch ProductBatch
    json.Unmarshal(batchJSON, &batch)
    return &batch, nil
}

    query := fmt.Sprintf(

        batchID,
    )
    resultsIterator, err := ctx.GetStub().GetQueryResult(query)
    if err != nil {
        return nil, err
    }
    defer resultsIterator.Close()

    var records []TraceRecord
    for resultsIterator.HasNext() {

        var record TraceRecord
        json.Unmarshal(queryResponse.Value, &record)
        records = append(records, record)
    }
    return records, nil
}

    "InspectorOrgMSP":  {"SUBMIT_REPORT", "VERIFY"},
    "RegulatorOrgMSP":  {"READ", "AUDIT", "RECALL"},
}

// CheckPermission 权限检查修饰器
func CheckPermission(ctx contractapi.TransactionContextInterface,
    requiredPermission string) error {
    mspID, err := ctx.GetClientIdentity().GetMSPID()
    if err != nil {
        return fmt.Errorf("身份验证失败")
    }

    permissions, exists := orgPermissions[mspID]
    if !exists {
        return fmt.Errorf("未知组织: %s", mspID)
    }

    for _, perm := range permissions {
        if perm == requiredPermission {
            return nil
        }
    }
    return fmt.Errorf("组织 %s 无 %s 权限", mspID, requiredPermission)
}

// InitiateRecall 发起产品召回（仅监管部门）

09 · 常见问题

常见问题解答

区块链溯源与二维码溯源有什么区别？

传统二维码溯源只是链接到一个中心化数据库的查询页面，数据可以被后台管理员随时修改。区块链溯源将关键数据的哈希值写入不可篡改的分布式账本，任何人都可以验证数据是否被篡改。二维码只是查询入口，区块链才是信任基础。

为什么不使用公有链（如以太坊）？

农产品溯源涉及企业商业机密（如供应商价格、产量数据），不适合全部公开在公有链上。联盟链允许控制参与节点和数据可见性，同时保留区块链的核心优势（不可篡改、多方共识）。此外，公有链的交易费用和 TPS 限制也不适合高频供应链写入场景。

上链的数据会不会太多导致性能问题？

平台采用"链上哈希 + 链下存储"的混合架构。大文件（图片、视频、完整检测报告）存储在 IPFS 中，链上仅保存哈希值（32 字节）。关键业务数据（批次信息、溯源记录、质检结果）直接上链。实测 TPS 可达 500+，完全满足供应链场景需求。

如果某个节点作恶怎么办？

联盟链采用 PBFT 共识机制，交易需要满足背书策略（如 3 组织中至少 2 个签名）才能写入。单个节点无法独自篡改账本。此外，每次写入都记录操作者身份（MSP 证书），可追溯至具体组织和个人。监管部门可随时审计异常操作。

小农户没有技术能力怎么使用？

平台提供极简的移动端 APP，农户只需拍照、填写基本信息、点击"上链"即可。IoT 传感器数据自动采集。平台运营方提供线下培训和 7×24 客服支持。实际试点中，60 岁以上农户经过 30 分钟培训即可独立操作。

溯源数据是否具有法律效力？

根据《最高人民法院关于互联网法院审理案件若干问题的规定》，区块链存证经核验无误的，可以作为认定事实的依据。本平台采用符合国密标准的加密算法，时间戳由区块链网络共同见证，司法认可度较高。已有多个法院采信区块链溯源证据的案例。
