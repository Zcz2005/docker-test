10B · 安全设计

多层安全防护体系

网络层 → 网关层 → 应用层 → 数据层 → 区块链层 五重防护

L1

网络层安全

  • VPC 私有网络隔离，区块链节点仅内网可达
  • WAF 防护 SQL 注入、XSS、CSRF
  • DDoS 防护（Cloudflare / 阿里云盾）
  • IP 白名单：Fabric Peer 节点间 mTLS 通信
L2

网关层安全

  • Kong JWT 插件验证 + Token 过期检查
  • API 限流：60 req/min（查询）、10 req/min（写入）
  • 请求签名验证（IoT 设备 HMAC-SHA256）
  • CORS 白名单 + HTTPS 强制跳转
L3

应用层安全

  • RBAC 角色权限：ADMIN / OPERATOR / VIEWER
  • 组织隔离：用户只能操作本组织数据
  • 输入校验：参数白名单 + 长度限制
  • 敏感操作二次确认（召回、批量删除）
L4

数据层安全

  • 密码 bcrypt (cost=12) 存储
  • 手机号/身份证 AES-256-GCM 加密
  • 数据库连接 SSL + 最小权限账号
  • 审计日志不可删除，按月分区归档
L5

区块链层安全

  • Fabric MSP 证书体系，每操作需私钥签名
  • 背书策略 2/4 组织签名方可写入
  • Chaincode 沙箱隔离执行
  • 合约代码第三方安全审计

双重认证流程详解

┌─────────────────────────────────────────────────────────────┐
│  第一层：应用认证（JWT）                                      │
│  POST /auth/login → 验证用户名密码(bcrypt)                    │
│  → 颁发 JWT {user_id, org_id, role, msp_id, exp: 24h}       │
│  → Redis 存储 session:{user_id}                              │
├─────────────────────────────────────────────────────────────┤
│  第二层：区块链认证（Fabric MSP）                              │
│  上链操作时：                                                 │
│  → 从用户关联的 fabric_cert 加载证书                          │
│  → Fabric SDK 使用私钥对交易提案签名                           │
│  → Peer 节点验证 MSP 身份 + 背书策略                          │
│  → Orderer 排序 → 写入各节点账本                              │
└─────────────────────────────────────────────────────────────┘

优化策略

瓶颈优化手段效果
溯源查询慢Redis 缓存 + PostgreSQL 复合索引 + 读写分离QPS 200→1200
区块链写入慢批量提交 + 异步确认 + 链下先写P99 800ms→280ms
